# dsh-kb

DSH 左侧栏里的本机知识库。把操作流程、操作规范、技术文档、注意事项、踩坑记录按「一级主题 / 二级主题」收好，打上自由标签，在对话里按需检索、按需引用。

- **只存不灌**：默认不往对话里塞正文，系统提示里只有一份短索引；要哪篇你点名，我再取。
- **两级主题 + 标签**：主题是树（如「Git 与代码托管 / Gitee / GitHub 连接」），标签横向串联；多个标签同时筛选。
- **全文检索**：标题、主题、标签、摘要、正文都能搜，按命中位置加权。
- **一个文件就是全部数据**：`kb.json`，纯 JSON，可直接备份、同步、手改。
- **接入对话**：输入框左边的「知识库」按钮按标签挑文档，点一下把引用写进输入框（正文不进去）。

## 环境要求

| 项目 | 要求 |
|---|---|
| DSH | 0.2.2-rc.1 及以上（0.2.x） |
| Node.js | ^22.19.0 或 >=24.0.0 |
| 操作系统 | Windows / macOS / Linux |

## 安装

### 方式一：npm（推荐）

```bash
npm install @qiyaogongfang/dsh-kb
```

在插件管理里安装 `@qiyaogongfang/dsh-kb`；或让 agent 执行 `plugin_manager` 的 `install_bundle`，target 填 `@qiyaogongfang/dsh-kb`。

> 注意：npm 上还有一个 `dsh-kb`，那是**别人**的另一个知识库包，不是这个项目。认准作用域 `@qiyaogongfang/`。

### 方式二：本地目录

```bash
git clone https://github.com/qiyaogongfang/dsh-kb.git
```

在插件管理里安装该目录；或让 agent 执行 `install_bundle`，target 填克隆目录的绝对路径。想改代码时用这种方式。

### 验证安装

刷新页面后左侧栏出现「知识库」图标；或让 agent 调用 `kb_search`，返回条目数即表示可用。

## 数据放在哪

| 位置 | 说明 |
|---|---|
| `~/.dsh-kb/data/kb.json` | 默认位置（用户目录下） |
| 环境变量 `KB_STORE_DIR` | 指定别的目录，例如放在同步盘上 |

写盘是「临时文件 + 原子替换」，同进程内串行；每次读写前比对文件 mtime，外部改过就重新载入，所以手工编辑 `kb.json` 也不会被旧缓存盖掉。

## 页面

- 左栏：全部 / 一级主题（点开看二级，带计数）
- 中栏：搜索框 + 标签筛选（多选＝同时命中）+ 文档卡片
- 右栏：正文（支持 Markdown 的小标题、列表、代码块、引用）、编辑、复制、删除

## 对话里的五个工具

| 工具 | 作用 |
|---|---|
| `kb_search` | 全文搜（标题/主题/标签/摘要/正文），可按主题、二级主题、标签过滤 |
| `kb_get` | 按 id 取正文；只给关键词时命中一篇就直接返回 |
| `kb_save` | 新建；带 `id` 时只覆盖给出的字段 |
| `kb_update` | 只改传入的字段，`clear` 清空指定字段 |
| `kb_delete` | 删一篇（模型会先确认是哪篇） |

## 系统提示里的开销

默认「只带索引」：分类计数 + 每个一级主题下最多 3 条标题。32 篇文档约 1100 字，不含任何正文；正文只在 `kb_get` 时才进上下文。

## 目录结构

```text
dsh-kb/
├── index.js            Host 半边：HTTP 接口 + 五个工具 + 系统提示索引
├── store.js            存储：JSON、两级分类、标签、全文检索
├── client.js           浏览器半边：侧栏面板 + 输入框引用按钮
├── cordis.patch.yml    插件行声明
├── locale/             zh / en 元数据
└── icon.svg
```
